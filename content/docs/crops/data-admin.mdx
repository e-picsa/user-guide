In the E-PICSA Dashboard, **Crop → Admin** (requires `crop.admin`) oversees the per-location water requirements behind every probability table: which districts are covered, whether each station's lookup tables are consistent, which varieties fall outside supported ranges, whether the field app is in sync, and which printable per-district versions are ready to share.

## Locations coverage

The chips summarise coverage at a glance: districts tracked, locations still missing requirements, paired and unique water-requirement definitions, and how many locations have probability data available. Each table row maps a location to its parent region, its requirement status, and the climate station it is paired with. Selecting a row lets you view or change the linked station, which decides the rainfall data behind that location's probability tables.

The Stations tab tracks whether probability lookup tables are consistently generated across stations. The **Probability Bounds** column compares each station's crop length (days), water requirement (mm) and planting date ranges and steps against the country majority — hover any status icon for the exact bounds and which dimension differs. The chips summarise the fleet: total stations, stations with no probabilities, and stations with inconsistent bounds. Filter to **Inconsistent Bounds** to isolate the outliers: an inconsistent station was generated with different ranges or steps (for example a wider day range but a narrower water range than the majority), so edge varieties may be included there but excluded everywhere else, or vice versa. Share inconsistent stations with the data team so future table calculations use consistent bounds.

## Crops quality control

<Screenshot
  name="crop/admin-crops.png"

    { x: 90, y: 44, label: 'QC Status — All Excluded, Partial Exclusion or Missing Definition; click a row for affected locations' },
  ]}
  caption="Crop Admin Crops tab (Zambia) — filtered to warnings and exclusions"

The Crops tab checks every variety's day and water requirements against the lookup bounds of each location's linked station. Day or water values outside the supported range exclude that variety from the generated table; season-length issues (over the local maximum season or the 360-day model limit) raise warnings instead, since the data system is expected to correct such probabilities rather than extrapolate. Red or amber values mark missed thresholds — click any row to inspect the affected locations and the exact threshold missed.

The chips summarise the catalogue: total varieties, varieties with warnings or exclusions, and duplicate variety definitions (the **Duplicates** filter, which replaces the old standalone tab). Filter to **Warnings & Exclusions** to review the affected varieties — day-range exclusions where a variety's length falls outside the station lookup bounds, plus any missing crop-data definitions — then click a row to see the exact locations and thresholds involved. Excluded varieties are omitted when tables are next regenerated; already bundled app tables are unchanged until re-exported.

    { x: 79, y: 56, label: 'Excluded — varieties removed by QC bounds at each location' },

  ]}
  caption="Crop Admin App Diff tab (Zambia)"
/>

App Diff compares the probability tables bundled in the field app against tables regenerated from live data-system records, with the **Apply QC Bounds** toggle applied. Each row is one location: app versus database variety counts, the excluded-variety count, and the share of changed probability cells. Statuses cover **New Exclusions**, **Differs**, **Missing in App**, **Orphaned in App**, **No Source Data** and **In Sync** — click any row to inspect the excluded varieties, the station bounds summary and the changed probability cells.

Locations showing 0% probability change differ by exclusions only — the underlying probability values are unchanged. A large percentage means the rainfall data behind the table differs (for example the location's linked station has changed), so inspect the row detail before re-exporting. Re-run this check after syncing or importing to confirm the app bundle is up to date.

## Print versions

  name="crop/admin-print.png"

The Print Versions tab builds one printable probability table per district: a Word document first, with the PDF converted from that rendered Word output so both formats share the same portrait A4 layout. Each document holds the district's localised table — title and district name, season-start dates with probabilities, per-variety days to maturity, water requirement and chance scores, plus the data-source footnote, the linked station and the generation date.

Tick the districts to include, grouped by province with running selected and available counts — **All** and **None** set the whole list at once. A row marked `(no data)` stays disabled: the district has no linked station, no water requirements, or its station has no usable probability or rainfall records. Tick the crop families to include alongside — each row shows how many varieties it holds, **All** and **None** again set the whole list, and everything is selected by default. Only the ticked families appear in the generated tables, and districts left with none of the ticked crops are skipped.

The icons at the end of each district row export that district immediately as Word or PDF using the current crop selection; the bulk buttons export every ticked district instead, staying disabled until at least one district and one crop are ticked. One file downloads directly, while several files arrive as a zip (with a subfolder per language when several languages are selected). English files keep the plain district name, while other languages append the language label. A progress bar tracks loading, generation, conversion and zipping; any failures are listed without blocking the remaining files, and the result line reports exported, skipped and failed counts.

## Upload and export

The **Upload** tab bulk-imports water requirements from CSV: **Template** downloads a sheet with one row per location, crop and variety; fill in the water-requirement column and **Upload File** (or paste the text) to preview changes. **Rows** shows values to be upserted, **Duplicates** flags repeated lines and **Errors** lists invalid rows; **Import** writes the valid rows (rounded to the nearest 5 mm). **Export App Data** generates the per-location probability tables as JSON and downloads them as a zip — the artefact bundled into the field app release.
